# Wooolfmesh GitHub Pages site

This repository contains the public GitHub Pages website for Wooolfmesh:

https://wooolfmesh.github.io/

**Your work should remember where you stopped.** Wooolfmesh is a local execution workspace that remembers your work between sessions. Return to the last outcome, decisions, sources, and next move.

The application is in private beta; its source repository and root license are not public. This repository contains the public website, not the application. Public requests go through [Support](https://wooolfmesh.github.io/support/) and do not guarantee access. No Store installer or measured productivity result is claimed.

## Technical approach

The site is plain static HTML, CSS and small progressive-enhancement JavaScript generated by a lightweight in-repo Node script. There is no framework runtime and no client-side rendering requirement. GitHub Pages serves the generated files directly from the repository root.

The generator keeps human pages, machine-readable JSON, JSON-LD schema, feeds, `llms.txt`, `llms-full.txt`, and `sitemap.xml` aligned from one public content model.

## Local preview

Install validation tooling once:

```bash
npm install
```

From the repository root:

```bash
python3 -m http.server 4173
```

Then open:

```text
http://localhost:4173/
```

## Quality checks

Generate the static site, Open Graph image, machine-readable files, and run static checks:

```bash
npm run check
```

The SEO/discovery contract and manual verification notes are documented in
[`docs/public-site-seo.md`](docs/public-site-seo.md).

Generate without checks:

```bash
npm run build
```

Check local links after starting the preview server:

```bash
npm run check:links
```

Run the focused accessibility crawl after starting the preview server:

```bash
npm run check:a11y
```

Format files:

```bash
npm run format
```

## GitHub Pages publishing

The live configuration checked on 2026-08-29 uses branch publishing:

- Source: deploy from a branch
- Branch: `main`
- Folder: `/ (root)`

Run `npm run check` before merging generated files. GitHub's managed **pages
build and deployment** workflow publishes the committed root; there is no
repository-authored validation workflow. Verify the successful deployment SHA
and live HTML/assets after pushing. A push alone does not prove publication.

The repository includes `.nojekyll` so GitHub Pages serves files as-is.

## Site structure

- `index.html` — landing page
- `product/index.html` — product modules
- `features/*/index.html` — focused feature pages
- `use-cases/*/index.html` — focused use case pages
- `roadmap/index.html` — Now / Next / Later roadmap
- `changelog/index.html` — public changelog
- `privacy/index.html` — local-first and privacy principles
- `install/index.html` — current install status and direction
- `about/index.html` — author and origin
- `faq/index.html` — visible FAQ with FAQPage JSON-LD
- `glossary/index.html` — product concept definitions
- `ai/*/index.html` — AI-readable overview, context and entity pages
- `404.html` — GitHub Pages not-found page
- `assets/` — CSS, JavaScript and brand SVG
- `feed.xml`, `atom.xml`, `feed.json` — public update feeds
- `site.webmanifest`, `robots.txt`, `sitemap.xml`, `llms.txt`, `humans.txt` — discovery and metadata files
- `favicon.ico`, `favicon.svg`, `assets/icons/` — browser, Apple touch, and maskable manifest icons generated from the existing mascot
- `assets/og.png` — 1200×630 Open Graph/Twitter preview generated from the existing mascot
- `llms-full.txt` — fuller AI-readable product context
- `data/*.json` — machine-readable product, feature, roadmap, glossary, FAQ and entity data
- `schema/*.jsonld` — reusable Schema.org JSON-LD snippets

## AI-ready files

- `llms.txt`: compact curated entry point for LLMs and answer engines.
- `llms-full.txt`: fuller product thesis, modules, privacy model, roadmap and glossary.
- `data/product.json`: canonical product entity.
- `data/features.json`: feature list.
- `data/roadmap.json`: Now / Next / Later roadmap.
- `data/glossary.json`: concept definitions.
- `data/faq.json`: visible FAQ as structured data.
- `data/entities.json`: semantic entity index.
- `schema/*.jsonld`: Schema.org snippets for WebSite, Product, SoftwareApplication, Person, FAQ, breadcrumbs, navigation, glossary terms and public data catalog.

## Safety rules

Do not publish:

- private vault data;
- secrets or tokens;
- sensitive screenshots;
- personal logs;
- client, employer, SAP or internal work data;
- fake users, fake testimonials, fake pricing or fake maturity claims.
